## Scope: what counts

A benchmark is listed here if it passes two gates. The examples below are real benchmarks; the ones that *fail* a gate are named, so the boundary is checkable. Close relatives that fail Gate 1 are kept separately under Near misses.

### Gate 1: Agentic

The system takes multiple steps, choosing each action after observing the result of the previous one, against executable tools or an environment.

**Passes:** take task 0 from *OpenEarthAgent* (in the table below): *"Which fire station and police station are closest to each other in Banff National Park, Alberta, Canada within 3000m buffered area?"* In the reference solution the agent first fetches the park boundary with a 3,000 m buffer and gets back a saved layer, then adds the fire stations inside it (two found), then the police stations (two found), and only then computes the distances and returns the closest pair. Each step works on what the earlier steps produced; that back-and-forth is what makes it agentic. (On its own this task is a map lookup, the kind Gate 2 below sets aside; it is here only to show the loop.)

**Fails, single-turn VQA.** *VRSBench* ([arXiv:2406.12384](https://arxiv.org/abs/2406.12384), NeurIPS 2024) hands a model a remote-sensing image, asks it to write a caption, locate an object, or answer a question, and grades that one-shot output. The model looks once and replies; there's no result to observe and no next move to pick, so there's no loop.

**Fails, one-shot code generation.** In *AutoGEEval* ([arXiv:2505.12900](https://arxiv.org/abs/2505.12900)) the model writes a piece of Google Earth Engine code that gets run once and scored. Generate, execute, score is a straight line: the model never sees how it went and adjusts.

### Gate 2: EO or geospatial workflow

A benchmark passes this gate when most of its tasks, or a good share of them, require the agent to work with information about the physical Earth derived from observation data: satellite, airborne, radar, in-situ, or products derived from them (reanalysis, land cover, NDVI, SST), possibly alongside other geospatial data.

Some tasks can be answered just by looking things up in a map database: where places are, how far apart they sit, how to get between them (OpenStreetMap, Google Maps). Nothing there is measured about the Earth. A benchmark made up mostly of such tasks does not pass; a handful of them inside an otherwise-EO benchmark is fine.

**Passes:** task 3 from the same *OpenEarthAgent* asks the agent to *"Assess moderate and strong urban growth or decrease in Nizwa Province, Oman between 2019 and 2024 using the NDBI change layer."* Here the agent has to call a tool to compute the NDBI (a built-up index) from satellite imagery for each year and then take the difference, so the answer comes straight out of the observation data.

**Fails:** *MapEval-API*, the tool-using part of MapEval (one of its three settings; [arXiv:2501.00316](https://arxiv.org/abs/2501.00316), ICML 2025 Spotlight), is a real multi-step agent, so it clears Gate 1. A typical task reads: *"I am driving to Brassica in Bexley via E Whittier St. After reaching Lockbourne Rd, where should I go next?"* But to solve it the agent only ever looks things up in a map (place search, place details, travel time, directions, nearby search), and nothing about the Earth is ever measured. A benchmark built mostly of tasks like this doesn't pass.
